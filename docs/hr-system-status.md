# ระบบ HR — ทำอะไรไปแล้ว ยังไม่ได้อะไร (4 ก.ย. 2569)

บันทึกไว้เพื่อวางแผน **ไม่ใช่สเปก** — สิ่งที่เขียนว่า "มีแล้ว" คือยืนยันจากโค้ด
จริง ส่วนสิ่งที่เขียนว่า "กฎหมายต้องการ" ยังไม่ได้ให้ที่ปรึกษาตรวจ

## มีแล้ว (ยืนยันจากโค้ด)

- **ทะเบียนพนักงาน** `/employees` — รหัสอัตโนมัติ `EMP-25xx-xxxx`, แฟ้มลับแยก
  `employees_private`, ผูกกับบัญชีเข้าระบบและไรเดอร์
- **ใบสมัครงาน** `/employees/recruitment` — สาย ใหม่ → ตรวจสอบ → สัมภาษณ์ →
  ข้อเสนอ → ตอบรับ → จ้าง (stepper), โน้ต HR, ลบใบพร้อมไฟล์เรซูเม่
- **รอบจ่ายเงินเดือน** — ภาษีหัก ณ ที่จ่าย + ประกันสังคม, บล็อกอนุมัติเมื่อกรอก
  ไม่ครบ, สลิป PDF
- **เอกสารภาษีรายปี** — 50 ทวิ, ภ.ง.ด.1ก
- **ปฏิทินกำหนดยื่น** `/tax-filings` — ภ.พ.30 / ภ.ง.ด.1 / 3 / 1ก + ประกันสังคม
- **เอกสารบุคคล** — สัญญาจ้าง · รับรองเงินเดือน · หนังสือเตือน (มีอายุ) ·
  ผ่านทดลองงาน · เงื่อนไข freeze ลงเอกสารตอนออก
- **ปิดการเข้าถึงอัตโนมัติเมื่อพ้นสภาพ** (ปิดอัตโนมัติ เปิดคืนต้องทำมือ)

## ยังไม่มี เรียงตามความคุ้ม

### ~~1. ที่แนบไฟล์เอกสารพนักงาน~~ ✅ ทำแล้ว (4 ก.ย. 2569)
ปุ่ม "แฟ้ม" ที่แถวพนักงาน → โมดอลเช็คลิสต์ + แนบ/เปิด/ลบไฟล์ · เก็บได้ครบตาม
รายการที่ตั้งใจ: สำเนาบัตร · ทะเบียนบ้าน · สมุดบัญชี · **สัญญาที่เซ็นกลับ** ·
ล.ย.01 · สปส.1-03 · วุฒิ · ใบขับขี่ · รูปถ่าย · อื่นๆ

**เช็คลิสต์ผูกกับประเภทการจ้าง ไม่ได้บังคับทุกคนเท่ากัน** — ฟรีแลนซ์ไม่ต้องมี
ล.ย.01/สปส.1-03 (ไม่ได้อยู่ ม.33 และไม่ได้หักภาษีแบบเงินเดือน) ส่วนใบขับขี่
บังคับเฉพาะคนที่ผูกบัญชีไรเดอร์ — เช็คลิสต์ที่ไม่มีวันครบสอนให้คนเลิกอ่านทั้งใบ

**ไฟล์เดินทางผ่าน callable ทั้งขาขึ้นและขาลง ไม่มี URL อยู่ที่ไหนเลย** ต่างจาก
เอกสารตัวอื่นในระบบ (voucher/ใบกำกับภาษี) ที่เก็บ tokenised download URL ไว้ให้
กดเปิดตรง — URL แบบนั้น**ข้ามกฎ Storage โดยการออกแบบ** ใครถือลิงก์ก็เปิดได้
ตลอดไป ซึ่งรับได้กับใบเสร็จของลูกค้าเจ้าของออเดอร์ แต่ไม่ใช่กับสำเนาบัตร
ประชาชนของพนักงาน

**และ `employee_files/` ไม่ต้อง deploy rules เลยทั้ง RTDB และ Storage** —
ตกกฎปิดของ root ทั้งสองที่อยู่แล้ว (Admin SDK เท่านั้นที่แตะได้)

**สิ่งที่พบระหว่างทำและควรตามต่อ: `isAdmin()` ใน `storage.rules` อาจไม่เคย
ทำงานเลย** — มันอ่าน **มิเรอร์ของ `/admins` ใน Firestore** เพราะกฎ Storage
อ่าน RTDB ไม่ได้ แต่ `firestore.rules` เขียนไว้ตรงตัวว่า "Firestore holds
search analytics and nothing else" และ **grep ทั้งสามรีโปแล้วไม่พบโค้ดที่เขียน
มิเรอร์นั้นเลย** ถ้ามิเรอร์ว่างจริง `firestore.get()` จะ raise ซึ่งแปลว่า
**ปฏิเสธเสมอ** → `/blog-covers`, `/blog-content` เขียนไม่ได้ และ **การลบ KYC
ของแอดมิน (`allow delete: if isAdmin()`) ก็ทำไม่ได้** ยังไม่ได้ยืนยันกับ
production (อ่าน Firestore สดจากที่นี่ไม่ได้) — **ต้องตรวจก่อนไปพึ่ง `isAdmin()`
กับงานใหม่ใดๆ**

### ~~2. ไทม์ไลน์ประวัติพนักงาน~~ ✅ ทำแล้ว (4 ก.ย. 2569)
ปุ่ม "ประวัติ" ที่แถวพนักงาน → โมดอลไทม์ไลน์ · เหตุการณ์ที่ระบบยังไม่รู้จักยัง
ขึ้นบนไทม์ไลน์พร้อมป้ายบอกว่าอ่านไม่ออก (ห้ามกรองทิ้ง)

**ที่ยังค้างจากงานนี้: `employee_events` ไม่มี `.indexOn: "employee_id"`**
(rules อยู่ที่ `bkk-frontend-next/database.rules.json`) ไม่มี index = RTDB อ่าน
ทั้งโหนดมากรองเอง วันนี้โหนดยังเล็กมากจึงยังไม่เจ็บ ทางแก้มีสองทาง: เพิ่ม index
แล้ว deploy rules จากอีกรีโป **หรือ** ย้ายไปเก็บซ้อนใต้
`employee_events/{employeeId}` แบบเดียวกับ `hr_documents` (ไม่ต้อง deploy rules
แต่ต้อง migrate ข้อมูลเดิม)

### 3. ตัวเตือนขึ้นทะเบียนประกันสังคม 30 วัน
มีช่องเลข ปกส. แล้ว แต่ไม่มีอะไรเตือนว่าคนใหม่ยังไม่ได้ขึ้นทะเบียน และ
**รอบจ่ายยังหักเงินสมทบและอนุมัติได้ทั้งที่ยังไม่ขึ้นทะเบียน** = หักเงินเขาไว้
แต่ยังไม่มีสิทธิ์

### 4. ล็อกอนุมัติรอบจ่ายเมื่อไม่มีเลขบัญชี
ตอนนี้บล็อกเฉพาะ "ไม่ได้ตั้งเงินเดือน" — ไม่มีเลขบัญชียังอนุมัติผ่าน แล้วไป
ตายตอนโอนจริง

ให้ไปเก็บผ่านแฟ้มพนักงานหลังอนุมัติจ้าง (เก็บเกินจำเป็นคือความเสี่ยง ไม่ใช่ความครบ)

### 6. ลา / เวลาทำงาน (โจทย์ข้อ 5) — ทำการลาแล้ว เหลือสองส่วน

**ทำแล้ว:** สิทธิ์การลาตามกฎหมาย 8 ชนิด · ยอดคงเหลือรายปี · ยื่น/อนุมัติใบลา ·
นับวันตามปฏิทินทำการของร้าน (ใช้ `settings/store/business_hours` ตัวเดียวกับ
หน้า checkout ของลูกค้า **ไม่มีปฏิทินวันหยุดชุดที่สอง**) · เตือนเมื่อสิทธิ์ที่
ตั้งไว้ต่ำกว่าขั้นต่ำตามกฎหมาย · หน้ารอบจ่ายแสดงวันลาไม่รับค่าจ้างของรอบนั้น

**ยังไม่ทำ 2 ส่วน:**

1. **การหักเงินอัตโนมัติ** — วันลาไม่รับค่าจ้างถูกบันทึกและแสดงแล้ว แต่ยัง
   ไม่หักเงินใคร **เป็นการตัดสินใจ ไม่ใช่ของที่ทำไม่เสร็จ**: รอบจ่ายวันนี้
   ไม่รู้จักการลาเลย ถ้าเปิดฟีเจอร์พร้อมต่อสายเข้ารอบจ่ายในคราวเดียว รอบแรก
   หลัง deploy ยอดของทุกคนขยับพร้อมกันโดยไม่มีใครเคยเห็นตัวเลขมาก่อน
   ให้ HR ได้เทียบตัวเลขที่ระบบนับกับที่ตัวเองรู้ก่อนสักรอบ แล้วค่อยต่อ —
   และตอนต่อต้องโผล่เป็นบรรทัด `absence` ที่มีชื่อ ไม่ใช่การหักที่ซ่อนในยอดรวม
2. **เวลาเข้า-ออกงาน (attendance)** — ยังไม่เริ่ม ต้องออกแบบก่อนว่าจะบันทึก
   จากอะไร (แอปไรเดอร์มีพิกัดอยู่แล้ว ส่วนพนักงานหน้าร้านยังไม่มีจุดบันทึก)

### 7. ไฟล์สำหรับยื่นแบบจริง — ทำได้ครึ่งทาง และครึ่งที่เหลือติดของนอกโค้ด

**ทำแล้ว:** CSV ของ ภ.ง.ด.1 และ สปส.1-10 มี**ทุกช่องที่แบบต้องการ เรียงตาม
ลำดับของแบบ รวมเลขประจำตัวประชาชน** (ก่อนหน้านี้มีแค่รหัสพนักงาน ซึ่งยื่นไม่ได้
จริงเพราะแบบทั้งสองฉบับผูกกับเลขบัตร 13 หลัก คนยื่นต้องเปิดแฟ้มลับหาทีละคน)
พร้อมรายชื่อคนที่ข้อมูลไม่ครบจนยื่นไม่ได้ **อยู่ท้ายไฟล์เดียวกัน** ไม่ใช่แค่
toast ที่ปิดไปแล้วหาย

**ยังไม่ได้ และเป็นสิ่งเดียวในแผนที่ยังไม่จบ:** ไฟล์ text สำหรับ**อัปโหลดเข้า
e-Filing โดยตรง** — layout ของไฟล์นั้น (ความกว้างคอลัมน์ / ตัวคั่น / ลำดับฟิลด์)
ต้องตรงทุกไบต์ระบบถึงจะรับ **และเราไม่มีสเปกฉบับจริงหรือไฟล์ตัวอย่างมายืนยัน**

การเดา layout แล้วติดป้ายว่า "พร้อมอัปโหลด" **แย่กว่าการไม่มีไฟล์เลย** เพราะคน
จะเอาไปใช้ตอนใกล้ครบกำหนดยื่นแล้วเจอว่าถูกปฏิเสธ ตอนที่ไม่มีเวลาแก้แล้ว

**สิ่งที่ต้องใช้เพื่อปิดข้อนี้ — อย่างใดอย่างหนึ่ง:**
- ไฟล์ตัวอย่างหนึ่งใบที่**เคยยื่นผ่านจริง** จากบัญชี (ของ ภ.ง.ด.1 และ/หรือ สปส.1-10)
- หรือเอกสาร layout จาก "โปรแกรมโอนย้ายข้อมูลใบแนบ" ของกรมสรรพากร และ
  สเปกไฟล์ของ e-Service ปกส.

ได้มาแล้วงานที่เหลือคือแปลง `buildFilingTable` เป็นตัวเขียนไฟล์ตาม layout นั้น
ซึ่งเล็ก เพราะข้อมูลทุกช่องพร้อมอยู่แล้ว
